# Molecule Testing

This role supports [Molecule](https://docs.ansible.com/projects/molecule/), an Ansible testing framework designed for developing and testing Ansible collections, playbooks, and roles.

## Prerequisites

To utilize Molecule you need to prepare several requirements:

- **x86** computer running one of these operating systems that make use of [systemd](https://systemd.io/):
  - **Archlinux**
  - **CentOS**, **Rocky Linux**, **AlmaLinux**, or possibly other RHEL alternatives (although your mileage may vary)
  - **Debian** (10/Buster or newer)
  - **Ubuntu** (18.04 or newer, although [20.04 may be problematic](https://github.com/mother-of-all-self-hosting/mash-playbook/blob/main/docs/ansible.md#supported-ansible-versions) if you run the Ansible playbook on it)
- `root` access on the computer which Molecule runs against
- [Ansible](http://ansible.com/) program
- [Python](https://www.python.org/)
  - Most distributions install Python by default, but some don't (e.g. Ubuntu 18.04) and require manual installation (something like `apt-get install python3`)
- [Docker](https://www.docker.com)
  - Access to Docker UNIX socket (`/var/run/docker.sock`) is required by default

## Installation

To set up the environment for using Molecule, run the command below on the terminal:

```bash
python3 -m venv ./molecule/venv
source ./molecule/venv/bin/activate
pip3 install -r ./molecule/requirements.txt
```

## Scenarios

Currently there is one testing scenario available.

### `default`

Tests a standard Duplicati installation, and in particular that the installation can take and return a backup:

- the container binds `/config`, `/backup` and `/source` to the host paths the role manages
- the container runs in the configured timezone, which only `env.j2` reaching the process can explain
- the API refuses unauthenticated requests, and refuses `changeme` — the password the container image falls back to when `DUPLICATI__WEBSERVICE_PASSWORD` is unset — while accepting the one the role configures
- the running server reports the version `duplicati_version` pins, on the `stable` channel
- a backup job created over the API archives a canary file from `duplicati_source_path` into `duplicati_backup_path`; the canary is then deliberately clobbered and a restore brings it back byte for byte

The service is deliberately not judged by `systemctl is-active` alone: the systemd unit sets `Restart=always`, so a crash-looping container still reports itself as active. Without `SETTINGS_ENCRYPTION_KEY` the container likewise stays up while Duplicati never starts and nothing ever listens on the port, which is why the HTTP and API assertions are the ones that carry weight.

## Running

By default it is configured to run the scenarios on Ubuntu 26.04.

```bash
molecule test --scenario-name default
```

You can utilize other distributions by setting one to the `MOLECULE_DISTRO` environment variable:

```bash
# Ubuntu 24.04
MOLECULE_DISTRO=ubuntu2404 molecule test --scenario-name default

# Debian 13
MOLECULE_DISTRO=debian13 molecule test --scenario-name default

# Debian 12
MOLECULE_DISTRO=debian12 molecule test --scenario-name default
```
